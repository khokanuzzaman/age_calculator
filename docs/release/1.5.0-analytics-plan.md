# Age Calculator 1.5.0 Analytics Plan

Use existing fixed product events to understand feature discovery and return
use. Do not add Firebase user IDs, personal identifiers, or new event
parameters as part of this plan.

## Funnel

```text
product_app_open
→ age_calculated
→ primary_profile_saved OR primary_profile_updated
→ birthday_saved OR timeline_event_added
→ birthday_reminder_enabled OR life_event_reminder_preferences_changed
→ notification_opened
→ birthday_shared OR birthday_wish_shared OR age_result_shared
```

Available fixed events also include `today_dashboard_viewed`,
`my_people_opened`, `life_timeline_opened`, `date_tools_opened`, individual Date
Tool usage events, notification opens, share actions, and review-prompt requests.

This is an aggregate event sequence, not a person-level joined journey. Inspect
existing event counts and coarse fixed parameters only.

## Areas to review after release

- Primary Profile adoption and clear/update activity.
- My People opens, saves, reminder settings, and favorites.
- Recurring Life Event creation and recurrence changes.
- Reminder enablement and notification opens.
- Birthday card sharing and Birthday Wish copy/share use.
- Date Tools screen and individual tool usage.
- `share_fallback_used` frequency relative to share actions.
- Firebase retention and session reports at aggregate level.

No target percentages are prescribed. Compare trends across releases and
investigate anomalies without attempting to identify individual users.

## Privacy boundaries

Events may include fixed enums, coarse age groups, booleans, or fixed source
labels. They must not include names, dates of birth, exact dates, person or Life
Event IDs, relationships, search queries, wish text, event titles, arbitrary
text, email, or phone. Notification routing IDs remain local and are not
analytics parameters.
