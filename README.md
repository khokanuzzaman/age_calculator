# Age Calculator

Age Calculator is a Flutter app for exact age and date math. It is designed
for Android and iOS and keeps personal inputs on the device.

## Current features

- Exact age calculation with lifetime totals, zodiac, numerology, and milestones
- Date Tools hub with Date Difference, Date Add/Subtract, Working Days,
  Weekday Finder, DOB Finder, Countdown, and Leap Year
- Saved birthdays with local yearly reminders
- Famous Birthdays and On This Day results
- Life Timeline and Life Calendar views
- Android home-screen widget for age and birthday/event information
- Light and dark themes, sharing, and privacy/about screens
- Conservative native in-app review prompts after meaningful local actions;
  Settings also provides an explicit Rate Age Calculator store action

## Data and connectivity

The calculators, saved birthdays, reminders, and preferences are local and
offline-first. Famous Birthdays and On This Day may make read-only HTTPS
requests to Wikimedia's On This Day endpoint; bundled curated data is used as
a local supplement/fallback. No account or backend is required.

Date Tools calculations remain local and offline. Working Days counts both
boundary dates and excludes public holidays; it supports Saturday/Sunday and
Friday/Saturday weekend presets without location detection or a holiday API.
Engagement state used to decide whether the platform review prompt is
appropriate is stored only in SharedPreferences and is never uploaded.

## Ads

The app uses Google Mobile Ads for banner, interstitial, and App Open ads.
AdMob configuration is platform-specific, test devices are configured in
`lib/core/ads/ads_config.dart`, and production builds must use valid app and ad
unit IDs. App Open loading is disabled when its production unit is missing or
malformed.

## Architecture

The code uses a lightweight Clean Architecture layout. Features live under
`lib/features/`; immutable models, repositories, pure date utilities, and
Riverpod notifiers keep business logic out of widgets. Shared platform
services are under `lib/core/`.

Analytics is represented by the vendor-independent `AppAnalytics` contract in
`lib/core/analytics/`. Production startup connects that contract to Firebase
Analytics when Firebase initializes successfully; a no-op implementation keeps
the app usable if initialization fails. Product events use coarse, non-personal
parameters only. Firebase automatically collects its own `app_open` event, so
the app's explicit launch event is named `product_app_open`.

Firebase Crashlytics receives uncaught Flutter and asynchronous fatal errors
through guarded global handlers. Expected fallbacks such as denied
permissions, ad failures, unsupported widgets, and Wikimedia network failures
are not reported as crashes. This phase does not add Firestore, Authentication,
Messaging, Remote Config, Functions, or another backend.

### Firebase setup

The dedicated Firebase project is `age-calculator-prod`.

- Android Firebase app: `me.khokan.agecalculator`
- iOS Firebase app: `me.khokan.agecalculator.ios`
- Generated configuration: `lib/firebase_options.dart`,
  `android/app/google-services.json`, and
  `ios/Runner/GoogleService-Info.plist`

If Firebase apps are recreated, authenticate the Firebase CLI and run
`flutterfire configure --platforms android,ios` from the project root. Do not
commit service-account files or CLI tokens. DebugView can be used for local
event verification by enabling the platform's Firebase Analytics debug mode
(`adb shell setprop debug.firebase.analytics.app me.khokan.agecalculator` on
Android, or the equivalent Xcode launch argument on iOS). For a local
Crashlytics check, temporarily use the official debug-only test-crash procedure
in a local branch and remove it before any release build.

Before publishing a build, the owner must review the Google Play Data safety
form, privacy-policy disclosure, and Apple App Privacy answers for the actual
Firebase Analytics and Crashlytics behavior of that release. This README is a
release checklist, not a legal privacy statement.

## Run locally

Install Flutter stable, then run:

```sh
flutter pub get
flutter run
```

Use an Android emulator/device or an iOS simulator/device. iOS builds require
the normal Xcode setup and signing configuration.

## Tests

Run static analysis and the test suite with:

```sh
flutter analyze
flutter test
```

## Release/configuration notes

- The installed version shown in Settings/About comes from `package_info_plus`
  and the package/build metadata in `pubspec.yaml`.
- Keep the Android and iOS AdMob app IDs and ad unit IDs separate.
- Review notification permission behavior and store privacy disclosures before
  release, including Firebase Analytics and Crashlytics data categories.
- Keep Firebase configuration generated by FlutterFire in sync with the
  registered Android and iOS app identifiers.
